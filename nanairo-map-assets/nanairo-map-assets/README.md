# ナナイロ ドロップス｜ステージマップ素材

承認済みの全50ステージマップから書き出した素材です。背景、操作部品、数字と座標を分けています。操作部品のPNGは透過付き、背景のWebPは不透明・可逆圧縮です。全素材と座標で同じ基準寸法を使います。

## 背景と縦スクロール

各背景は **1206 × 2622 px** です。画面の上から下へ、下表の順に隙間なく並べます。プレイヤーは最下段のステージ1から上へ進みます。道は背景に含まれ、継ぎ目まで描かれています。エリア名のプレートと文字は上から重ねます。

| 上からの順 | ファイル | エリア | ステージ |
|---:|---|---|---:|
| 1 | `backgrounds/map_05.webp` | お菓子のお城 | 41〜50 |
| 2 | `backgrounds/map_04.webp` | 金平糖の星空 | 31〜40 |
| 3 | `backgrounds/map_03.webp` | キャラメル通り | 21〜30 |
| 4 | `backgrounds/map_02.webp` | ラムネの森 | 11〜20 |
| 5 | `backgrounds/map_01.webp` | ドロップの丘 | 1〜10 |

- 各エリアは `position: relative; width: 100%; aspect-ratio: 1206 / 2622` の要素で表示します。背景の `img` は `display: block; width: 100%; height: auto`。ラッパー、画像、座標の基準幅を揃えます。
- 縦スクロール領域は `overflow-y: auto`。エリアの間はマージン、パディング、隙間を0にします。画像読み込み前から寸法を確保し、初期位置のジャンプを防ぎます。
- 幅だけを画面に合わせ、高さは縦横比に従わせます。`object-fit: cover` や画面高への強制伸縮を使うと道と座標がずれます。個別エリアが表示領域より高くなる場合は、そのままスクロールします。
- iPhoneの縦画面では、画面全体を `100dvh` で確保し、固定ヘッダーとスクロール領域に分けます。セーフエリアの余白はヘッダーの上とスクロール領域の最下部に取ります。エリア間の高さや座標計算に混ぜないでください。

## ステージボタンと数字

`stage-buttons/` のPNGはすべて **192 × 192 px**。共通のアンカーは **(96, 96)**、メダル本体の直径は約135 pxです。

| ファイル | 表示方法 |
|---|---|
| `stage-cleared.png` | クリア済み。共通の朱赤のメダルにチェック付き |
| `stage-current.png` | 現在挑戦中。金色のメダル |
| `stage-locked.png` | 未解放。青みのあるグレーのメダル |
| `stage-hard-frame.png` | ハード用の金色の縁。状態ボタンと同じ中心に配置 |
| `stage-super-hard-frame.png` | スーパーハード用の二重金縁。状態ボタンと同じ中心に配置 |
| `stage-lock-icon.png` | 鍵バッジ。メダル中心から右へ48 px、下へ46.5 pxずらして配置 |

進行データから `current`、`cleared`、`locked` のいずれかを選びます。判定順は現在地、クリア済み、その他です。難易度は進行状態と別に判定し、`hard` または `superHard` の枠を追加します。重ねる順は下から輝き、難易度枠、状態ボタン、数字と鍵です。プレビューでは1〜4がクリア済み、5が現在地、6〜50が未解放です。JSONの難易度は承認モックアップの表示例です。正式な難易度が別にある場合はゲームデータを優先します。

数字の色はクリア済み `#fce9b6`、現在地 `#6d372f`、未解放 `#fff0c5`。数字はHTMLで出力します。ステージボタンと数字の位置は、同じ192 px正方形の中心で揃えます。端末上のサイズはすべて背景と同じ倍率で変換します。

```css
.stage-pin {
  position: absolute;
  transform: translate(-50%, -50%);
  display: grid;
  place-items: center;
}
.stage-pin > .stage-layer,
.stage-pin > .stage-number {
  grid-area: 1 / 1;
}
.stage-layer {
  display: block;
  width: 100%;
  height: 100%;
}
.stage-number {
  display: grid;
  place-items: center;
  width: 100%;
  height: 100%;
  font-family: "DejaVu Serif", Georgia, serif;
  font-weight: 700;
  font-variant-numeric: tabular-nums;
  line-height: 1;
  padding: 0;
  pointer-events: none;
}
```

ボタン要素の余白、枠線、既定の背景をリセットし、CSSでボタン画像を背景にする場合も `center / contain` で配置します。ステージの状態は `aria-current` や読み上げラベルでも分かるようにします。鍵や輝きは独立したレイヤーにし、タップ判定はステージボタンにまとめます。

- 1桁は63 px、2桁は52.5 px、3桁は42 pxを元画像基準の文字サイズとします。いずれも背景と同じ倍率を掛けます。桁数で変えるのは文字サイズだけです。
- 検証画像では、数字の実際に描画される輪郭の外接矩形を中心に揃えています。iPhoneで代替フォントに切り替わり、CSSの行ボックス中心と見た目に差が出る場合は、`CanvasRenderingContext2D.measureText()` の `actualBoundingBox*` で補正できます。中心揃えのアンカーを動かす必要はありません。

## 座標データ

`data/stage-positions.json` の原点は**各背景の左上**、ステージのアンカーは**ボタン中心**です。座標は承認画像を作ったレイヤーの中心点から、書き出し倍率3を掛けて取得しています。

| フィールド | 意味 |
|---|---|
| `stages[].stage`、`area`、`background` | ステージ番号、所属エリア番号、背景ファイル名 |
| `stages[].xPx`、`yPx` | 1206 × 2622 pxの元画像におけるボタン中心 |
| `stages[].x`、`y` | 各背景の幅・高さで割った0〜1の相対座標 |
| `stages[].width`、`height` | 各座標の基準寸法 |
| `stages[].difficulty` | `normal`、`hard`、`superHard` |
| `areas[].label` | エリアプレートの左上と幅・高さ。元画像基準のpx |
| `tileOrderTopToBottom` | 背景の表示順 |
| `assetScale` | ボタン、文字、鍵、うさぎのサイズとオフセット |
| `preview` | 検証画像用の進行状態と所持コイン |

`left: x × 100%`、`top: y × 100%` をエリア内のステージボタンに指定し、`translate(-50%, -50%)` で中心を重ねます。表示幅を `displayWidth` とすると、共通倍率は `s = displayWidth / 1206`。ピクセル座標を使う場合は `left = xPx × s`、`top = yPx × s`、画像枠は `192 × s` の正方形です。背景幅が変わるときは同じ `s` で再計算します。

「現在地へ」を押したときは、対象エリアのスクロールコンテンツ内の先頭位置に `yPx × s` を足して、現在地の縦位置を取得します。その位置から表示領域の高さの半分程度を引き、スクロール可能な範囲に収めます。初回表示も同じ処理で現在地へ移動できます。ヘッダーをスクロール領域の外に置く場合、ヘッダー高をこの式に加えません。

## うさぎとUI

うさぎは `characters/rabbit.png`（420 × 417 px、透過）。現在地にだけ表示します。標準の表示枠は **174 × 204 px**。ボタン中心から **右へ102 px、上へ198 px** の点を表示枠の左上にし、比率を保って中央に収めます。表示倍率 `s` を適用します。端に近い場合は横位置を調整して画面内に収め、道やボタンの座標は保持します。

| `ui/` のファイル | 寸法 | 用途 |
|---|---:|---|
| `header.png` | 1206 × 279 px | 赤・金の固定ヘッダー背景 |
| `stage-label.png` | 447 × 135 px | 「ステージ」と現在の番号を載せる枠 |
| `coin-label.png` | 465 × 135 px | コイン所持数を載せる枠 |
| `coin-icon.png` | 78 × 81 px | コイン枠の左側に重ねるアイコン |
| `settings.png` | 138 × 138 px | 設定ボタン。読み上げ名は「設定」 |
| `current-location.png` | 156 × 54 px | 「現在地へ」を重ねるボタン枠。現在地の小ラベルにも使用可 |
| `area-label.png` | 744 × 117 px | エリア名を載せる無地プレート |
| `sparkle.png` | 240 × 240 px | 現在地の背面の光輪と星。ボタンと同じ中心 |

ヘッダー素材の左上座標は、背景の左上を原点としてステージ枠 **(39, 99)**、コイン枠 **(507, 99)**、コインアイコン **(549, 126)**、設定 **(999, 99)** pxです。文字の基準中心は「ステージ」**(201, 166)**、現在の番号 **(405, 167)**、所持コイン **(771, 167)** pxです。文字は動的に表示してください。

ヘッダーはスクロールするマップの外側に置き、上部に固定します。iPhoneでは `viewport-fit=cover` を指定し、ヘッダーの上に `env(safe-area-inset-top)` 分の赤い余白を設けてステータスバーと重ならないようにします。画面下端の操作ボタンには `env(safe-area-inset-bottom)` を加えます。「現在地へ」は文字を動的に中央に重ね、タップ領域は44 CSS px以上を確保します。エリア名は `areas[].label` の枠内に描画します。

## ステージ51以降の追加

新エリアは道の接続位置と幅を合わせて、既存エリアの上に追加します。背景の幅・高さ、`areas`、`tileOrderTopToBottom` とステージごとの中心座標を登録します。初期の5枚と寸法を揃えると同じレイアウトで扱えます。数字と各状態の素材は再利用できます。新しい背景にもステージ番号、ボタン、うさぎを含めません。
