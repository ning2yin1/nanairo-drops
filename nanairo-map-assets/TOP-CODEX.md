# ナナイロ ドロップス｜Codex向け TOP画面作り直し指示

既存リポジトリのTOP画面を、承認済み画像を使って作り直してください。対象はiPhone縦画面のPWAです。背景を上下左右の端まで表示し、ロゴ、飴、缶の輪郭の縦横比を保ってください。上下の金縁はできる限り残してください。「スタート」はこれまでどおり既存のマップを開きます。

## 作業範囲

- 現在のエントリーポイント、TOPからマップへの遷移方法、TOPの既存スタイルと画像参照先を最初に確認してください。TOPに限定したレイアウトに置き換え、旧TOPの余白、サイズ制限、画像を引き伸ばす処理、二重の背景処理を整理します。
- マップの画面・遷移先・進行データ・セーブ・ステージ座標・素材は維持してください。既存のGitHub Pagesの公開設定、PWAマニフェスト、Service Workerの動作も引き継ぎます。キャッシュが旧画像を参照する場合は、既存方式に従って変更対象のキャッシュだけを更新してください。
- 素材の参照先はリポジトリ内の実ファイルを使用し、GitHub Pagesのリポジトリ配下でも解決できる相対パスまたは既存ビルドのベースパスを使ってください。新しい依存関係は不要です。

## 使用するTOP素材

| ファイル | 寸法 | 用途 |
|---|---|---|
| `nanairo-top-assets/title-background.png` | 707 × 1536 px | ボタンを外した、承認済みの缶背景 |
| `nanairo-top-assets/start-button.png` | 630 × 204 px | 余白込みの透過「スタート」画像 |
| `nanairo-top-assets/title-reference.png` | 707 × 1536 px | 画面全体の見た目と位置の照合用 |

背景とボタンを表示用に使用してください。ボタン素材の左上は、背景素材の左上から **右へ36 px、下へ1240 px** です。透過余白を含む画像全体に対する座標なので、画像をトリミングすると位置がずれます。絵の内容・色・ロゴは元のPNGをそのまま使用してください。

## 表示方法

1. TOP専用の表示領域をビューポートいっぱいに作り、親から継承した固定幅・固定高さ・余白・セーフエリアのパディングが背景を縮めていないことを確認します。iPhoneではホーム画面から起動したPWAを基準に確認します。必要なら viewport の `viewport-fit=cover` を使い、変更した場合はマップのセーフエリアも確認してください。ブラウザUIが出入りするSafariタブでは、実際に利用可能な表示領域を使用します。
2. TOP領域の実測幅を `W`、高さを `H` とし、下記の共通倍率で画像全体を均等に拡大します。背景はビューポートを埋める `cover` 相当で、はみ出した分をTOP領域の内側でクリップします。背景が単色の帯に置き換わったり、画像の端を引き延ばして貼り足したりする方式は使わないでください。
3. 背景とボタンを同じアートボードに配置します。縦横別々の倍率、背景だけ `object-fit: cover` でボタンを画面に対する割合で置く実装、背景とボタンで別の基準を使う実装は避けてください。

```text
s = max(W / 707, H / 1536)
artWidth = 707 × s
artHeight = 1536 × s
offsetX = (W − artWidth) / 2
offsetY = (H − artHeight) / 2

背景  左上 (offsetX, offsetY)  サイズ (artWidth, artHeight)
ボタン 左上 (offsetX + 36 × s, offsetY + 1240 × s)
       サイズ (630 × s, 204 × s)
```

実装は、707 × 1536のアートボード全体を一度だけ均等に拡大する方法でも、上記と同じ結果になる計算で両画像を配置する方法でも構いません。コンテナの寸法が変わったら再計算します。安全領域は背景を縮めるための余白に使わず、実際のボタンが押せる位置かを判断するために使います。ボタンは `<button type="button" aria-label="スタート">` とし、二重に文字を描かず、既存マップへの遷移処理を呼び出してください。

## 金縁と表示の優先順位

- iPhoneの縦画面では、まず中心配置で上下の金縁を確認してください。たとえば402 × 874 CSS pxの表示領域なら、元素材との比率差は横方向の合計約0.29 CSS px分で、上下の金縁を残せる計算です。この程度の比率差で下に大きな帯が出る場合は、素材の比率より表示領域の高さ・余白・画像の重ね方を調べてください。
- Safariのバー表示などで表示領域の縦横比が変わり、全面表示と金縁の両方を完全には維持できない場合は、**全面表示と正しい縦横比、押せるスタートボタンを優先**します。クリップ量が最小になる配置を基本に、必要なら同じアートボード全体の上下位置だけを、画面を埋める範囲 `H − artHeight ≤ offsetY ≤ 0` で調整してください。実際に金縁がどこまで見えるかはスクリーンショットで確認します。

## 完了確認

- iPhone 17相当の402 × 874 CSS pxの表示領域でTOPを撮影し、承認画像と比べてください。上下左右に意図しない帯や継ぎ目がなく、ロゴや飴が変形せず、上下の金縁が残っていることを確認します。
- もう一つ短めの縦ビューポートでも確認し、背景が全面を覆い、ボタンが元の絵の位置からずれず、タップできることを確認します。シミュレーターや開発者ツールで確認した場合は、その環境と実測したビューポート寸法を報告してください。
- スタートを押して既存のマップが開き、表示・縦スクロール・現在地と既存の進行が保たれることを確認してください。
- GitHub Pages相当のサブパスから画像が読み込めることと、変更後のTOPがキャッシュで旧版に戻らないことを確認してください。変更ファイルとテスト結果を報告してください。
