# TOP全画面・タッチ操作検証（2026-11-10）

## 原因と変更

旧実装でもhtml/body/main/title-screenは402×874のビューポートと一致していた。
一方、Safe Areaを62/34pxとした場合、画像は約398.86×866.56、位置(1.56,25.33)。
375×667、Safe Area20/0では約331.71×720.66の画像に縮小。
単色グラデーションで差分を埋める設計のため、画像の外側は缶として連続しなかった。
最新ユーザースクリーンショットはこの依頼に添付されておらず、端末固有の表示状態は未確認。

新実装はルートとCanvasを(0,0)から画面の幅・高さ全体に配置。
中央の絵柄とボタンは同じ倍率・座標系。元画像の金属の縁を画面端に配置し、
中央との間には端の無地テクスチャだけを延長。画像素材ファイルの変更なし。
Safe Areaと縁の内側に果物・ロゴ・ボタンを保つ。100dvhの変化はResizeObserverで再計算。
html/body全体のスクロール防止・document全体のtouchmoveキャンセルは使用しない。
将来のマップは独立したスクロールコンテナにできる。

## 実行したブラウザ検証

Chromium、モバイル・タッチ有効。Safe AreaはCSSで値を注入して計算を検証。
iOS Safariの実機検証ではない。

| viewport | Safe Area上/下 | Canvas（変更後） |
| --- | --- | --- |
|402×874|62/34|402×874|
|402×759|0/0|402×759|
|390×844|47/34|390×844|
|375×667|20/0|375×667|
|430×932|59/34|430×932|
|320×568|20/0|320×568|
|874×402|0/21|874×402|

各条件で親ルート/Canvasの位置と寸法、Canvasの全ピクセルに透明な未描画領域がないこと、
文書のスクロール幅/高さがviewportと一致すること、果物上端/ボタン下端が安全領域内であることを確認。
スタート→準備中→戻る→再スタートの操作が成功。HTTPエラー/JavaScript例外なし。
ブラウザへの2本指ピンチ操作でvisualViewport.scale=1を確認。
キャンセル可能なgestureイベント・複数指touchmove・連続touchendの抑止も検証。
単指touchmoveとゲーム画面外のgestureイベントはキャンセルされない。
仮のマップコンテナはtouch-action:pan-yでscrollTop=400までスクロール可能。

旧v2のService Workerを登録したクライアントに新ビルドを提供し、v3への移行、
v2キャッシュの削除、オフライン再読み込み、オフラインでの画面往復を確認。
`npm run build`、`git diff --check`も成功。

## 制約

SafariのブラウザUI（アドレスバー等）はWebページから描画/非表示を強制できない。
PWAではblack-translucentのステータスバーとviewport-fit=coverを使用する。
iOSのアクセシビリティ機能によるシステムズームは制御対象外。
SafariのバージョンやOSのジェスチャー処理は実機での最終確認が必要。
GitHub Pagesへのこの環境からの直接アクセスはネットワーク許可がなく未確認。
