# TOPの単一画像表示への修正（2026-11-11）

## 確認した原因

旧実装はCanvasへ中央・左右・上下・金属の縁を別々に描画していた。
位置と倍率の異なる画像片の境界で模様や黄色い線が不連続になり、
元画像のない模様の反復と引き伸ばしが発生する構造だった。
Canvasの未描画ピクセルがないことだけでは、画像の連続性は検証できていなかった。
添付スクリーンショットの下部にはページ側の暗赤色が露出していた。
その端末の実測値は未取得のため、下部帯を生んだSafari固有の寸法差や旧キャッシュの影響は未確定。

## 新しい構造

- ビューポートを覆うmainと、その内側を覆うTOPコンテナ。
- 背景は元のPNGを単一のimgで表示。object-fit:cover、画像分割や複数背景なし。
- title-layout.jsでcoverの一様倍率と切り取り位置を計算し、同じ座標でボタンを表示。
- ロゴとボタンをSafe Area内に保持。画面比率の差は画像外周の切り取りで吸収。
- 背景にtransformなし。CSSの重複した旧配置指定とCanvasの描画処理を撤去。
- rootは100dvhで初期表示し、Visual Viewportの高さに同期してツールバー/PWAの寸法差に追従。
- Safe Areaのpaddingで背景を縮めない。準備中画面のUIには従来どおりSafe Areaを使用。
- ゲーム画面限定のジェスチャー抑制を維持。将来のマップは独立した縦スクロール領域にできる。

## 実行した確認

`scripts/check-layout.cjs`をChromiumのモバイル/タッチモードで実行。
iOS実機での検証ではなく、Safe AreaはCSS変数へ値を注入して確認した。

| viewport | Safe Area 上/下 | root / TOP / 背景img |
| --- | --- | --- |
|402×874|62/34|すべて402×874|
|378×818（添付と同じ比率）|47/34|すべて378×818|
|402×759|0/0|すべて402×759|
|390×844|47/34|すべて390×844|
|375×667|20/0|すべて375×667|
|430×932|59/34|すべて430×932|
|320×568|20/0|すべて320×568|

すべて座標(0,0)、背景PNGの要素数1、Canvas数0、object-fit:cover、transform:none。
背景とボタンの座標系が707:1536であること、ロゴとボタンの表示範囲、スクロールなしを確認。
画像の伸縮は等比。背景の分割をなくしたため、元画像内の黄色い斜線は一枚のまま連続する。
378×818のスクリーンショットを目視確認し、左右の模様の反復・継ぎ目・下部単色帯なし。
スタート→準備中→戻る→再操作、ピンチイン/アウト、ダブルタップ（倍率1）、
高さを60px縮めて戻す操作、画像HTTPエラーなし・JavaScript例外なしを確認。

v3のService Workerを登録した旧クライアントで新ビルドに更新し、v4への移行、
旧キャッシュ削除、オフラインでの背景表示と往復操作を確認。
CSS/モジュールのURLをv4に更新し、新SWはHTTPキャッシュの再検証と即時有効化を行う。
`npm run build`および`git diff --check`が成功。
